    MCP server guide¶

    genefox mcp serves GeneFox's analyses to an MCP client over stdio. Each tool runs the same analysis code a GeneFox app screen runs, and returns that screen's numbers as JSON. Most tools also write a PNG figure and can write the screen's CSV, a GeneFox recipe, or a single-figure HTML document.

    See Install & resources and the CLI reference.

    Starting the server¶

    genefox mcp --resources /path/to/Resources --output-dir ~/genefox-out

    genefox mcp never prints the CLI's update notice and never checks for updates; update an installer install with genefox update from a terminal.

    Option Meaning
    --resources <dir> A copy of the app's scientific resources directory; or GENEFOX_RESOURCES, then <resolved executable directory>/../share/genefox/Resources, then <X>.app/Contents/Resources for a Contents/Helpers/genefox or Contents/MacOS/genefox executable, then a source checkout's the app's scientific resources directory for a binary under its .build folder. Automatic roots require ScientificResources.json; every source uses the same integrity checks. With no folder, a missing one, or one without ScientificResources.json, the server does not start (status 78, the reason on stderr). If its digests or the gene reference then fail the background check, gene tools answer resource_unavailable naming the reason, and no figure is drawn.
    --cache-dir <dir> Download cache; or GENEFOX_CACHE_DIR. Default ~/Library/Caches/GeneFoxCLI on macOS, $XDG_CACHE_HOME/GeneFoxCLI (or ~/.cache/GeneFoxCLI) on Linux. Mount a persistent volume in containers; on WSL prefer the Linux filesystem.
    --output-dir <dir> Where figures, CSVs, recipes and HTML are written; or set GENEFOX_OUTPUT_DIR. Default <system temp>/genefox-mcp. Files are only ever created there, never overwritten.
    --enable-legacy-tools Also list the five legacy tools, which take local paths or URLs.
    --imported-store <dir> The imported-dataset store the legacy render_recipe may read. A tool argument cannot name a store.
    --allow-root <dir> An extra local read root for the legacy validate_recipe/render_recipe paths, repeatable; or GENEFOX_MCP_ALLOWED_ROOTS (path-separated). The output directory and the imported store are always roots; a model-named path outside every root is refused.
    --warm <list> Prefetch toil, pancan and/or project ids such as TCGA-BRCA, in the background.
    --call-timeout <seconds> One deadline (1–3600 s) for every call, replacing each tool's own.
    --help, -h Print the usage and exit 0.
    --max-concurrent-calls <n> How many tools/calls run at once (1–64; default half the processors, 2 to 4). Up to 16 more queue; beyond that a call answers rate_limited. See Limits.

    An option error exits with status 64, and a missing resources folder with status 78, before the server reads any input. Otherwise the server prints one self-check line to stderr and then serves until stdin closes, for example:

    genefox mcp: pid=152 resources=/path/to/Resources (flag) inventory=available reference=available font=ok pin=ok cache=/home/user/.cache/GeneFoxCLI out=/tmp/gfout allowlist=on legacy=off deadline=per-tool calls=4 queue=16 entitlement=free(not-linked) flavor=release version=1.1.0+unknown

    Some fields in that line need explanation:

    • allowlist=on: in mcp mode the network transport admits only an exact list of public-data hosts, over HTTPS on port 443, and re-checks every redirect. PedcBioPortal, loopback and GeneFox's own cloud hosts are deliberately absent.
    • entitlement=free(not-linked): see Entitlements.

    Progress. A tools/call whose request carries params._meta.progressToken gets a notifications/progress every 10 seconds until it answers, with the seconds elapsed as progress (no total: a call cannot know its own length), so a client that resets its timeout on progress keeps waiting through a slow first call. Without a token nothing is sent; each slow tool's description gives its expected time.

    Stdout carries only protocol messages. Logs, including one genefox mcp: host_not_allowed … line per refused request, go to stderr.

    Connecting a client¶

    Every client starts the server the same way: it runs the command genefox mcp [options] and talks to it over stdin and stdout. Use absolute paths, because a client may start the server from any working directory.

    Long calls need a long client timeout. The server's own deadlines are 300 s, or 900 s for the slow tools (see Limits), and a cold first call can take minutes. Several clients stop waiting sooner than that by default; each client section below says how to raise its limit.

    Claude Code¶

    claude mcp add --transport stdio genefox --scope user \
  --env GENEFOX_OUTPUT_DIR=$HOME/genefox-out \
  -- /usr/local/bin/genefox mcp --resources /path/to/Resources

    Or commit a project-scoped .mcp.json:

    {
  "mcpServers": {
    "genefox": {
      "command": "/usr/local/bin/genefox",
      "args": ["mcp", "--resources", "/path/to/Resources"],
      "env": { "GENEFOX_OUTPUT_DIR": "/Users/you/genefox-out" }
    }
  }
}

    Claude Code reads these timeout settings, all in milliseconds:

    • MCP_TIMEOUT limits server startup.
    • MCP_TOOL_TIMEOUT, or a per-server "timeout" in .mcp.json, limits a single tool call.

    Check the Claude Code MCP documentation for the current defaults.

    Claude Desktop¶

    Claude Desktop uses the same mcpServers shape, in claude_desktop_config.json:

    {
  "mcpServers": {
    "genefox": {
      "command": "/usr/local/bin/genefox",
      "args": ["mcp", "--resources", "/path/to/Resources", "--output-dir", "/Users/you/genefox-out"]
    }
  }
}

    I could not verify the file's location or Claude Desktop's tool-call timeout here; check Claude Desktop's documentation for both.

    Codex¶

    codex mcp add genefox --env GENEFOX_OUTPUT_DIR=$HOME/genefox-out \
  -- /usr/local/bin/genefox mcp --resources /path/to/Resources

    Or in ~/.codex/config.toml:

    [mcp_servers.genefox]
command = "/usr/local/bin/genefox"
args = ["mcp", "--resources", "/path/to/Resources"]
env = { GENEFOX_OUTPUT_DIR = "/Users/you/genefox-out" }
startup_timeout_sec = 30
tool_timeout_sec = 960

    Codex documents defaults of startup_timeout_sec = 10 and tool_timeout_sec = 60. A 60-second tool timeout ends most cold GeneFox calls early, so raise it as shown. Check Codex's documentation for the current keys.

    OpenCode¶

    In opencode.json (or opencode.jsonc):

    {
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "genefox": {
      "type": "local",
      "command": ["/usr/local/bin/genefox", "mcp", "--resources", "/path/to/Resources"],
      "environment": { "GENEFOX_OUTPUT_DIR": "/Users/you/genefox-out" },
      "enabled": true,
      "timeout": 960000
    }
  }
}

    OpenCode's per-server timeout is in milliseconds; its documented default is 5000. In OpenCode 1.18.34 it bounds every request to the server, tool calls included, not only the tool listing: a 75-second call is cut off at "timeout": 60000 with MCP error -32001: Request timed out, and completes at "timeout": 960000 . Set it to 960000 so the 900 s tools can finish.

    Protocol surface¶

    The server speaks protocol version 2024-11-05 and reports the server as genefox version 1.1.0. Each line on stdin is one JSON-RPC 2.0 message, and each response is one line on stdout. The server handles these messages:

    Message Behaviour
    initialize Returns capabilities: {tools: {}}, serverInfo and instructions: the usage rules a model should follow, which summarise this guide.
    ping Returns {}.
    tools/list The tools this process may offer (see Entitlements and Legacy tools). The list and the dispatcher read the same registry, so a listed tool is always callable.
    tools/call Runs a tool. Its result is one text content item holding the tool's JSON. isError: true means the tool ran and reports a tool error.
    notifications/cancelled Cancels the call named by requestId. The cancelled call writes no response.
    any other id-less message Silence.
    any other method JSON-RPC error -32601.

    Argument conventions¶

    TCGA/GDC human gene inputs use GeneFox's existing approved-symbol and curated-alias reference: for example, Her2 resolves to ERBB2 and PD-L1 to CD274. An approved symbol takes precedence over an alias. Imported feature IDs and GEO probes retain their literal spelling and organism-specific meaning.

    Cohort expression, gene signatures, heatmaps and differential panels return data.gene_resolution: the original token, canonical symbol, exact dataset field, dataset version, mapping release and source checksums. GDC STAR expression uses the verified annotation declared by the dataset sidecar. A custom loader's unknown mapping source is represented as null. Provider-supplied dataset versions use the bounded untrusted_dataset_version key; reports and CSV retain the complete version. With csv: true, these tools also write gene_resolution_csv; the primary data CSV keeps its existing columns. Captured reports retain the mapping provenance, and saved views retain the requested tokens.

    gene_info accepts a symbol or a quoted Entrez ID and supports human genes only. A numeric ID must match the final human record exactly; a different or redirected record is refused as gene_identity_mismatch. A genuine missing record is gene_not_found; malformed or incomplete upstream metadata is upstream_malformed. The returned symbol is NCBI's official name, while summary and aliases remain under untrusted_* keys.

    Every tool reads its arguments under these rules:

    • Closed schemas. Every input schema has additionalProperties: false. An unknown key is refused with invalid_argument, naming the key in field, so a misspelt key is reported instead of silently changing the analysis.
    • null means absent. For an optional field, an empty string (after trimming) also counts as absent.
    • Types. A wrong JSON type is refused with a sentence such as gene: expected a string, got a number. JSON true decodes as a boolean, not as the number 1.
    • Strings are trimmed, then checked against a maximum length and, where the tool has one, a whole-string pattern. A TCGA gene symbol must match ^[A-Za-z0-9][A-Za-z0-9.-]*$, with at most 30 characters, and is upper-cased as the TCGA screens do. The GTEx gene is trimmed but not upper-cased, as that screen does.
    • Enumerations must be one of the listed values. A project id is matched case-insensitively and answered in canonical form (tcga-stad becomes TCGA-STAD).
    • Integers and numbers are checked as doubles before any conversion. A value must be finite and within the schema's minimum/maximum, and an integer must also be whole. A value out of range is refused, never clamped.
    • String lists are trimmed and de-duplicated case-insensitively. A list over its maximum count is refused, never truncated.
    • Figure size. A tool with a size argument also accepts width_in, height_in, dpi (72–1,200) and the figure-style keys (survival_detail, show_row_counts, show_caption_color_keys, show_figure_legends). A custom size must stay within the app's side limits, 8,192 px per side and 16 megapixels in total. dpi is accepted only together with width_in and height_in.
    • Figure file name. A tool with a size argument also accepts output_name, a stem for the figure's file name in place of the tool name and the title's slug. It takes letters, digits, ., _ and -, starts with a letter or digit, and is at most 64 characters. A name with a separator (/, \, :), a .., or any other character is refused before the tool runs. Only the figure's descriptive part changes; see Figures.
    • A heatmap opened from a differential-expression result (from_differential_expression) records its comparison and top_n in its deep_link and recipe (de: and de_top: flags). open_destination and a recipe replay reopen it as one: the comparison is rerun and its top genes taken again over its samples under the DE group strip, as the apps reopen it; a recipe flag this build cannot read runs nothing. A comparison by molecular subtype does not draw the default Subtype strip beside the DE group strip that already shows it.
    • Figure axes (GeneFox Pro). The tools whose figures have continuous axes also accept x_min, x_max, x_scale, y_min, y_max, y_scale, value_min, value_max and value_scale, each tool only for the axes its figures have: x and y for a scatter or volcano (geo_gene_correlation, tcga_top_correlates, geo_top_correlates, tcga_differential_expression, and the PC1 x PC2 scatter of tcga_sample_pca and geo_sample_pca, which refuse a customization with biplot, scree or correlated_genes, whose figures have no customizable axis), value for a box, violin or strip (tcga_tumor_normal, tcga_pan_cancer_expression, tcga_compare_cohorts, reference_treehouse_expression, gtex_tissue_expression, cbioportal_expression), and the axes of whichever figure figure_kind or the grouping draws (tcga_expression: all three; tcga_gene_signature: x for the histogram, value for the grouped box; geo_series_expression: x for the ungrouped histogram, value for a one-factor box, violin or strip (tcga_expression's ecdf has no customizable axes), x and y for a continuous characteristic's scatter, none for a two-factor view; without geometry a value key means the box and an x or y key the scatter, and a characteristic the matrix shows to be the other kind is refused once it is read). A bound is a finite number in data units on either scale; a scale is linear (the default) or log10. A histogram's x bounds restrict its binning range. Values outside a bound, and values at or below zero on a log axis, are not drawn; the figure says how many in its caption and its description. A reversed range, a non-positive bound on a log axis, an axis the figure does not have, or a figure kind with no customizable axis (a survival curve, a two-factor box, an ECDF) is refused with invalid_argument. Every one of these keys is Pro (publicationStudio) and refused with entitlement_required unless the server's context grants that capability (see Entitlements). A customization is saved with what the call writes: a recipe records it as one axes: flag on its destination (the same keys, axes:value_min=7;value_max=12;value_scale=linear) and in its presentation metadata, whose Methods line names the axes; open_destination and genefox render pass a recorded flag back to the tool, so a replay draws the same axes and stays Pro-gated, and a flag this build cannot read runs nothing. A CSV is the data, unchanged (csv.customization and csv.customization_note say so); an HTML document embeds the customized engine figure (html.parity: app_document_engine_figure); figure: false returns the data and echoes customization with a customization_note. Significance brackets on a customized value axis test the values it shows, on its scale, as ggplot2 does. A caption that cannot fit, or would squeeze the plot, is refused with the size that would work; it is never cropped. A drawn customized figure reports figure.customization (the value's stable JSON) and parity: engine_only. genefox render takes the same values as --x-min, --x-scale and so on, for an imported plot or signature replay and for a signature's --r-script (x for the score histogram, value for the one-factor box plot). The script draws them as GeneFox does: values outside a bound, and values at or below zero on a log axis, are removed before anything is binned or summarized, which is ggplot2's scale-limits behaviour (scale_x_continuous(limits = ), scale_x_log10()), not coord_cartesian()'s zoom; the already-filtered geometry is drawn with oob = scales::oob_keep and the figure's caption. A public recipe replays the axes it recorded, and refuses the flags.

    Every refusal is a tool error whose code is invalid_argument and whose field names the argument. It happens before any network request. No argument of a non-legacy tool is a filesystem path or a URL to fetch. open_destination takes a genefox:// link, which it decodes as the app's route planner does; it does not fetch it.

    Results and the untrusted_* trust model¶

    A successful result is a JSON object. Analysis tools return tool, data, display (the screen's sentences and tables, to quote verbatim), caveats and provenance. provenance holds sources, genefox_cli (the version), transport: "live" (or "record" / "replay"), fetched_at and, where a screen applies, parity_screen.

    When a result list is capped, truncated discloses its field, kept and total counts. One capped list produces an object; multiple capped lists produce an array of those objects, so every cap is disclosed.

    Third-party text is never placed under a plain key. Text that comes from a dataset, a portal or a model goes under a key named untrusted_*. Examples are GEO sample characteristics and author labels, CSV headers named after them, Reference and cBioPortal labels and study text, local-model replies, and a deep link that carries GEO text (untrusted_deep_link). The initialize instructions tell the model to treat these fields as data, never as instructions. Each string is capped at 120 characters, with a trailing … when cut. A few diagnostic fields use their own larger caps; for example, GEO supplementary refusal diagnostics allow 512 characters for a file name and 1,200 for a reason. When a file name is derived from GEO text, the written path is returned as untrusted_path / untrusted_file_name.

    Figures¶

    TCGA and GEO expression offer a cumulative distribution (geometry=ecdf) over the retained observations, including constant-valued samples. GEO distribution exports retain grouping controls and apply any keep_groups subset before pooling values. It uses the same GeneFox engine as the cards on the apps. Its export recipe preserves the ECDF selection. ECDF axes are fixed; custom bounds or scales refuse before loading data.

    Expression distributions offer box, strip and violin plots, with histogram or ECDF where that screen's schema offers them. The expression bar option is retired. For one release, MCP accepts the older bar and median_bar spellings as box-plot aliases and returns a migration caveat. Saved views, links and recipes that recorded a bar also open as a box plot with a notice; genefox render writes the notice to stderr. Keep the returned caveat with the figure. Genuine count, proportion and ranked bar charts retain their own geometry.

    A figure tool draws through GeneFox's shared engine and writes its figure create-only under the output directory. The optional format argument picks the file: png (the default, a raster), svg (vector, with editable text) or tiff (raster, the extension .tif). Every figure is written in all three formats from the same drawing, and format follows the file's extension and media type (format and mime_type in the result). SVG keeps the figure's labels as editable text. It then returns figure with these keys:

    Key Meaning
    path, file_name, bytes, sha256, width_px, height_px The file written. For a PNG the pixel size is read from the file itself.
    format, mime_type The file's format (png, svg or tiff) and its media type.
    geometry, size What was drawn. size is the preset token, or custom.
    description The engine's description of the figure.
    alt_text Alt text: the engine's own summary and caveat if it has one, otherwise the description, otherwise a sentence built from the title.
    data_table [{label, value}], one row per drawn element (group, arm, legend row, or point), in drawn order.
    data_table_rows, data_table_truncated, data_table_note The table's row count before the cap; whether the table was cut; and, only when it was, a sentence saying so.
    data_table_unavailable Replaces the table when the engine attached no element description.
    parity, parity_screen, parity_note See Parity tokens.

    File names. A figure's file name is

    <NN>_<tool>_<slug>_<W>x<H>in[_<dpi>dpi].<ext>
    • NN is the figure's number in this server session, counted from 01 and never reused, so two figures from one session never share a name, even when they come from the same tool.
    • tool is the tool that drew the figure, and slug is the title's slug. output_name, when given, replaces tool_slug and nothing else.
    • W and H are the size in inches, to one decimal; dpi is the resolution. A vector file (svg) has no resolution, so its name has no _<dpi>dpi.
    • ext is the one extension the format takes: png, svg or tif.

    Example: 01_tcga_pan_cancer_expression_box-plot_7.2x6.0in_300dpi.png.

    A name that is already taken is never replaced. The file takes -2, -3 and so on before its extension, so 01_..._300dpi-2.png is the second file with that name.

    The data table is capped at 200 rows. Only scatter and volcano figures, which have one row per point, reach that cap. Rows past it are not lost: they are still in the tool's data and CSV, which are never capped by this.

    When a figure's labels are third-party text, description, alt_text and data_table are replaced by untrusted_description, untrusted_alt_text and untrusted_data_table, never returned beside them, and every cell is capped as above. The counts and the truncation note are GeneFox's own text and stay under plain keys.

    A figure can also be missing:

    • figure_unavailable: no font, no output directory, nothing to draw, or a write failure.
    • figure_refused: the engine's refusal sentence.

    The server never draws an unlabelled figure.

    With inline_image: true, a figure tool also returns an MCP content item {"type":"image","data":"<base64 PNG>","mimeType":"image/png"} alongside the existing text item. The cap is 1,048,576 PNG bytes before base64 encoding, inclusive. For a larger PNG, no image item is returned; figure.inline_image_omitted contains {"reason":"size_limit","bytes":N,"maximum_bytes":1048576}. The PNG is still written create-only and its file metadata is still returned. The argument defaults to false; omitting it preserves the existing result bytes. This lets clients display figures without access to the server's output directory. An unavailable or refused figure adds no image content. The legacy render_recipe reports a render verdict and has no shared figure result.

    With html: true, a tool also writes the screen's single-figure HTML document. That document's <img alt> is the figure's alt_text, and after the figure it has a "Figure 1 data" table of the same rows, with the same 200-row cap. Every string in it is HTML-escaped. If no figure was drawn, the result carries html_unavailable instead; tcga_case_expression always answers html_unavailable, with the reason, because its screen exports no HTML.

    csv: true and recipe: true work the same way. They return csv or recipe (with path, bytes and sha256), or csv_unavailable / recipe_unavailable with a reason.

    Parity tokens¶

    The figure.parity and html.parity fields say how an output relates to what the app exports:

    Token Where Meaning
    app_export_identical figure.parity The app screen's PNG export calls the same shared function with the same arguments.
    engine_only figure.parity Drawn by the shared engine, but the screen has no PNG export to match; for example, the screen snapshots the view, or the figure was drawn with customized axes, which no screen draws yet.
    font_mismatch figure.parity Replaces either value above when the figure font failed its SHA-256 pin. The glyph widths may differ from the app's.
    app_document_engine_png html.parity The app's HTML document over the screen's title, subtitle, source and table, embedding the engine's PNG bytes. Apple re-encodes the same pixels.
    app_document_engine_figure html.parity As above, but the screen snapshots this figure, so the app's own document embeds a snapshot where this one embeds the engine figure.

    The related fields are:

    • figure.parity_screen: names the app screen the figure corresponds to.
    • provenance.parity_screen: names the screen whose numbers the tool reproduces. The two can differ; for example, a Survival tab's numbers can come with an engine-drawn figure.
    • parity_note: a sentence stating exactly where the output departs from the app, where there is something to say.

    Entitlements (GeneFox Pro)¶

    The server fails closed. Pro tools are listed and callable only when the server grants the required capability. Hidden tools answer -32602 Unknown tool. No argument, flag, environment variable or file grants Pro access.

    Pro tools: batch_explorer_run, publication_studio_export, dataset_radar_check and dose_response. Without a live grant a Pro tool is not listed, and a direct call is refused with entitlement_required before any file is opened. genefox curated dose <view> <package-dir> runs dose_response from a terminal.

    account_status reports linked: false, entitlement: "not_linked", granted_capabilities: [] and cloud_ai: "off", with the caveat "Linking a GeneFox account to this server is not available in this version."

    lab_collaboration_status, cloud_sync_status, cloud_sync_now and cloud_sync_store are free. They need a linked account, so in this version they report that none is linked.

    Account and cloud authority¶

    Account linking, cloud retry and the dataset finder are not available in this build:

    • Disabled by default. Each server context starts with an absent authority: no service, no profile, no evidence. No production tool creates a privileged publication, no MCP argument can supply a service, evidence or approval, and the authority is shut down at EOF.

    • One-use human approval. The design requires a decision made in the human helper's own interface for linking and for each cloud request. An approval is bound to one exact request, host and authority generation, and is consumed when used.

    • Model-run commands are never human approval. An agent running a terminal command, or a model setting a force-style flag, is not the human decision the design requires. No tool input can stand in for it.

    Local conversations (tcga_ask_open, geo_ask_open, ask_turn, ask_close) use only a host-owned local model and execute no analysis on their own. local_model_status reports whether a local model is ready. On the Linux build it reports conversation: "unsupportedPlatform" and single_query: "unsupportedPlatform".

    Limits, deadlines and cancellation¶

    Limit Value Behaviour
    Request line size 4 MB (maximumLineBytes) Refused before decoding: -32700 "Request line exceeds 4 MB", id null.
    JSON nesting depth 32 levels, the envelope counting as 1 (maximumNestingDepth) Refused before decoding: -32700 "Request nesting exceeds 32 levels", id null.
    Per-call deadline 300 s by default; 900 s for the slow tools; 30 s for ask_turn (see the catalogue) The call answers timed_out (retryable). The abandoned work may finish and fill the cache, so a retry is usually faster.
    --call-timeout 1–3600 s Replaces every tool's deadline.
    Concurrent calls (--max-concurrent-calls) 1–64; default half the processors, 2 to 4; 16 more may queue Beyond the queue: rate_limited (retryable, details.source: genefox_server), not run. Queued time counts against the deadline (timed_out with details.queued: true).
    Early cancellations remembered 256 A notifications/cancelled that arrives before its request is remembered, and that request is then dropped.
    GEO search cursors 32 active searches, 15-minute idle expiry, 5,000 results per search cursor_capacity (retryable), cursor_expired, cursor_busy (retryable), pagination_limit.
    Local conversations 2–8 sessions and 8–64 MB of snapshot memory in total, both measured from physical memory; 15-minute lifetime session_capacity, session_expired, session_busy (retryable).

    The deadline timer is a Dispatch timer outside Swift's cooperative pool, so a saturated pool cannot delay the timed_out verdict.

    Concurrency. The read loop starts one task per request line immediately, so ping and tools/list are never queued behind a slow analysis. Only tools/call passes the call limiter: at most --max-concurrent-calls run at once and up to 16 more wait, first come first served; a call beyond that answers rate_limited at once. A slot is held by the work, not the answer, so a timed-out or cancelled call keeps it until its kernel returns.

    Error codes¶

    JSON-RPC errors¶

    Code When
    -32700 Invalid JSON, a line over 4 MB, or nesting deeper than 32. Answered with id null.
    -32601 Unsupported method.
    -32602 tools/call named a tool that is not listed. For a legacy tool started without the flag, the message is Tool not available: <name> is a legacy tool; start the server with --enable-legacy-tools.

    Tool errors¶

    A tool error is a normal tools/call result with isError: true, whose text is {"error": {"code", "message", "retryable", "field"?, "details"?}}. The codes used in this tree are:

    Code Meaning
    invalid_argument An argument was refused (field names it), or an input file or report was unreadable.
    entitlement_required A GeneFox Pro argument (field) the context does not grant (details.capability); nothing was run.
    resource_unavailable The scientific resources, gene reference, or a report asset is missing.
    gene_not_found, ambiguous_gene The gene did not resolve, or resolved to more than one row (details lists the candidates).
    no_data, no_expression_data Nothing to analyse, or no expression matrix (GEO, Expression Atlas, supplementary files).
    not_runnable, unsupported_here, query_refused The analysis is refused with the app's sentence; the screen has no tool here; or the shared planner/validator refused the query.
    conflicting_loci, incomplete_family (retryable), upstream_partial_failure (retryable) Pan-cancer and pan-cancer survival assembly failures.
    upstream_unavailable (retryable), upstream_http (retryable for 5xx), rate_limited (retryable, retry_after), upstream_malformed, response_too_large Network and source failures.
    host_not_allowed The server reached a host outside the allowlist (details.host).
    seam_unavailable A platform seam was not installed.
    geo_search_failed, cursor_expired, cursor_busy, cursor_capacity, pagination_limit GEO search and pagination.
    session_capacity, session_expired, session_busy, session_limit, model_unavailable, invalid_model_response Local conversations.
    output_unavailable report_export_pdf has no usable output directory.
    timed_out (retryable, details.deadline_seconds), cancelled The deadline passed, or the call was cancelled.
    internal Anything else, with its message.

    Some file outputs fail without failing the call. They are reported beside the result as figure_unavailable, csv_unavailable, recipe_unavailable or html_unavailable.

    Legacy tools¶

    --enable-legacy-tools adds five tools that take a local path or a URL, which no other tool does:

    • report_export_pdf: a saved report to a PDF, written create-only to the output directory.
    • report_export_html: a saved report to one self-contained HTML document, written create-only to the output directory.
    • validate_recipe: the CLI's validate verdict.
    • fetch_url: fetches through the installed transport. In mcp mode that is the allowlisted transport. maximumBytes must be between 1 and 100,663,296, the default is 50 MB, and text over 100,000 bytes is returned as a preview.
    • render_recipe: the CLI's render. An imported recipe reads only the store the server was started with (--imported-store); the model cannot choose a store, and a storage_directory argument is refused.

    Without the flag they are neither listed nor callable (-32602).

    A legacy tool reports a failure as isError: true with a plain-text sentence beginning error:, not as the {"error": {...}} object described under Tool errors. For example, fetch_url to a host outside the allowlist answers error: The GeneFox MCP server does not contact <host>: it reaches only the public-data hosts its tools need., and the server logs genefox mcp: host_not_allowed request host=<host> to stderr.

    list_coverage¶

    list_coverage takes no arguments. It returns one row per free app operation: row, operation, app_screen, mcp_tool (or null), status and note. The status is one of available, partial, planned or not_available_headless. The result also has counts per status. On this build, list_coverage reported 54 available, 17 partial, 12 planned and 6 not available headlessly. A final row summarises Pro operations without naming any; a context granted a Pro tool's capability also gets that tool's row after it. Call list_coverage for the current state rather than relying on these numbers.

    Legacy local recipe paths are limited to the output directory, --imported-store, and repeatable --allow-root directories (also GENEFOX_MCP_ALLOWED_ROOTS, separated by : on POSIX or ; on Windows). The server resolves links before testing containment, then opens that canonical file without following replacement links. Validation and rendering consume the bytes from that held handle, rather than reopening the model's path. Devices, sockets, FIFOs, directories, and files above 64 MiB are refused with local_path_* codes; the byte ceiling also applies if a file grows while it is read. fetch_url accepts only an allowed public HTTP(S) URL and never turns a file: URL into a local read.
